브라우저 초안은 **기기 간 동기화하지 않는다**. 다른 기기에는 서버가 받은 지시가 보인다. 브라우저 탭을 완전히 닫거나 저장소를 지우면 로컬 초안·미확인 ID가 사라질 수 있으므로, 새 탭에서는 서버 대기열을 먼저 확인한다. 실패한 요청을 새로운 문장이나 새 ID로 무조건 반복하지 않는다.

## 검증 구분

구문 검사 통과. **전체 47개 중 39개 통과, HTTP 8개는 포트 권한 제한으로 차단**됐다. 포트 없는 시험은 TCP·TLS·물리 기기 시험으로 계산하지 않는다. 전체 테스트 명령의 종료 코드는 1이며 이를 전체 성공으로 기록하지 않는다.

- 클라이언트 시험: 링크에 인증·임의 쿼리를 포함하지 않음, 재시도 ID 유지, 새 초안 보존, 작업별 분리, 저장 실패 시 전송 금지, HTTP 오류·타임아웃 시 자동 재전송 없음.
- 서버 시험: 동시 승인·거절 중 1건만 전달, 기록 재로딩, 승인 결과 유실·`sending` 상태 재시작 시 중복·반대 결정 차단.
- 요청 처리기 통합 시험: 실제 `createApp`의 요청 처리 함수를 메모리 요청/응답으로 호출한다. 실제 앱 인증·Git·디스크 상태와 모의 엔진을 사용하며 포트는 열지 않는다. 두 세션의 동일 작업 조회·추가 지시·승인·거절·로그아웃 분리·재로그인·중복 방지·재시작을 검증한다.
- 기존 HTTP 통합 시험은 그대로 유지했다. 이 실행 환경에서는 8개가 `listen EPERM`으로 차단되므로 전체 성공으로 표시하지 않는다.
- 브라우저 모의 화면 확인을 시도했으나 도구가 `file:` URL을 보안 정책으로 차단했다. 이를 다른 브라우저 경로나 우회 실행으로 대체하지 않았다. 이번 M2 UI의 실제 브라우저·390px 시각 검증은 미완료다.
- 운영 서버의 모델 호출·물리 맥북/모바일 검증은 수행하지 못했다. 네트워크가 제한된 셸의 curl 실패를 서비스 종료로 판정하지 않는다. LaunchAgent PID 22584는 계속 실행 중이다.

### 백엔드 반영

정적 화면 파일은 기존 서버가 요청마다 읽기 때문에 새로고침 시 바뀔 수 있지만, **승인 기록·중복 전달 보호는 백엔드 재시작 후 활성화**된다. `/api/system` 응답의 `features.permissionDecisions === true`로 새 백엔드를 구분한다. 이전 서버에 연결한 새 화면은 승인 기록 기능의 업데이트 필요를 표시한다.

이 작업에서는 운영 서비스를 중단하지 않았다. 네트워크 제한 때문에 재시작 후 건강 상태를 직접 확인할 수 없는 상황에서 기존 서비스를 임의로 내리지 않는다.

1. 맥미니 일반 터미널에서 다음을 실행해 모든 테스트가 통과하는지 확인한다.

   ```sh
   cd /Users/ukkhnn/Developer/personal-ai/agent-workspace/app
   npm run check
   npm test
   ```

2. 진행 중·승인 대기·질문 대기 작업과 대기열을 확인한다. 활성 작업이 없거나 정리된 경우 [RUNBOOK의 정상 재시작](../RUNBOOK.md#4-서비스-재시작)을 따른다. 강제 종료·PID 파일 삭제·중복 `npm start`는 사용하지 않는다.
3. 브라우저를 새로고침하고 앱에 재로그인한다. 기존 작업이 보존됐는지 확인한다. 업데이트 필요 안내가 없어졌는지 확인한다.
4. 아래 실제 기기 시나리오를 실행하고 결과를 기록한 뒤 M2 전체 완료 여부를 결정한다.
