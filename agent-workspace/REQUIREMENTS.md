# 현재 요구사항 — v0.2

갱신일: 2026-10-28. 상태: **제품 방향 및 초기 실행 방식 확정 / 상세 설계·기술 검증 전**.

## 기준 문서와 적용 순서

[PRD.md](PRD.md)는 사용자가 제공한 v0.1 원문으로 보존한다. 이 문서는 이후 대화에서 확정한 변경사항을 기록하며, 충돌하는 항목에는 이 문서의 확정 내용을 우선 적용한다. 변경하지 않은 기존 요구사항은 유지한다. [DECISIONS.md](DECISIONS.md)는 선택 근거와 남은 질문을 기록한다.

## 프로젝트 목표

- `personal-ai`: 최종적으로 개인 AI 비서를 구축한다.
- `agent-workspace`: 그 기반인 자체 AI 워크스페이스를 구축한다.
- 현재 최우선 사용 사례는 개발이다. 기능 구현을 우선하고 다른 버그 수정을 병행할 수 있어야 한다.
- 일반 비서로 확장할 수 있도록 설계한다. 초기에도 일부 기능을 기대하지만, 구체적인 기능과 출시 범위는 아직 정하지 않았다.

## 첫 버전의 개발 흐름

1. Mac mini의 프로젝트에 대해 개발 작업을 시작한다.
2. 작업별 브랜치와 worktree를 할당해 다른 작업과 파일 수정을 분리한다.
3. AI가 해당 작업 폴더에서 코드 수정·명령 실행·테스트를 수행한다.
4. MacBook을 닫아도 중앙 실행은 유지된다.
5. 모바일에서 같은 작업의 대화·진행 상황을 확인하고 추가 지시 또는 명령 승인을 전달한다.
6. AI가 작업 브랜치에 자동으로 커밋하고 해당 원격 작업 브랜치에 push한다.
7. 사용자가 변경 코드와 테스트 결과를 확인한다. 최종 병합은 사용자 승인 후 진행한다.

자동 커밋·push의 시점과 빈도, PR 생성 여부, 병합 방식, 충돌 처리 및 승인 이후 변경 발생 시 처리 방식은 상세 설계에서 정한다. 작업 브랜치 자동 push는 main 등 통합 대상 브랜치에 직접 push하거나 강제 push하는 정책을 뜻하지 않는다.

## 추가 지시와 중단

- 일반 메시지는 현재 작업에 대한 추가 지시로 전달한다. 메시지 전송만으로 진행 중인 실행을 중단하지 않는다.
- 현재 작업을 계속하면서 다음 처리 가능한 시점에 추가 지시를 반영하고, 전달·대기·반영 상태를 구분해 표시한다.
- 연결 도구가 실행 중 지시 반영을 지원하지 않으면 대기열에 넣고 대기 상태를 표시한다.
- 중단 버튼은 메시지 전송과 분리해 제공한다. 사용자가 명시적으로 중단을 요청할 수 있다.
- 중단 요청과 실제 중단 완료를 구분한다. 하위 명령·프로세스의 중단 범위, 대기 중 지시의 처리, 변경 파일 보존 및 재개 방식은 후속 설계에서 정한다.

## v0.1에서 달라진 범위

- Mac mini 중앙 실행은 권장안에서 첫 버전의 확정 방향으로 변경했다.
- 기존 도구 연결은 자체 환경과 함께 지원할 요구사항이다. 특정 도구 채택이나 기존 앱 대화 전체 가져오기를 확정한 것은 아니다.
- 기존 Phase 3의 파일·명령·Git 실행, 승인, 실행 로그 및 변경 확인을 첫 버전으로 앞당긴다.
- 첫 버전에 같은 프로젝트의 개발 작업 병행과 worktree 분리를 포함한다.
- 원격 Worker는 후속 확장이다. 첫 버전의 필수 검증 범위에 포함하지 않는다.
- 멀티모델·템플릿·메모리·예약·루틴 요구사항은 유지한다. 상세 지원 순서는 로드맵과 후속 논의로 구체화한다.

## 첫 버전 검증 항목

아래 항목은 확정 요구사항을 검증하기 위한 초안이다. 정량 목표와 실패 시 동작은 상세 설계에서 정한다.

- [ ] MacBook → 모바일 → MacBook 전환 후 같은 대화·작업 상태를 확인한다.
- [ ] 접속 기기가 종료되어도 Mac mini의 작업은 계속된다.
- [ ] 다른 기기에서 보낸 일반 메시지가 실행을 중단하지 않고 추가 지시로 전달되며, 전달·대기·반영 상태를 확인한다.
- [ ] 실행 중 지시 반영을 지원하지 않는 연결에서는 지시를 대기열에 보존한다.
- [ ] 별도 중단 버튼으로 중단을 요청하고, 실제 중단 완료 여부를 확인한다.
- [ ] 승인 요청을 다른 기기에서 처리하고, 중복 요청으로 명령이 재실행되지 않는다.
- [ ] 작업별 코드 변경, 테스트 결과, 실행 실패를 확인한다.
- [ ] 같은 프로젝트의 두 작업이 각각 다른 브랜치·worktree에서 실행되고 다른 작업의 파일을 덮어쓰지 않는다.
- [ ] 재접속 시 실행 중·승인 대기·완료·실패 상태를 구분한다.
- [ ] 작업 브랜치의 자동 커밋·push 결과를 확인하고, 최종 병합은 사용자 승인 없이는 수행되지 않는다.
