# 아키텍처

상태: **개념 초안 / 미확정**.

기준: [PRD §5](PRD.md)의 시스템 아키텍처 초안. 아래는 기획서의 개념 구조이며, 구현 기술의 확정을 의미하지 않는다.

## 개념 구조

접속 기기 → 사설 네트워크·인증 → 애플리케이션 서버 → 실행 계층 → 저장 계층

- 접속 기기: MacBook, 모바일, 브라우저
- 애플리케이션: 세션, 대화, Agent, 템플릿, 메모리, 예약 및 알림 관리
- 실행: 외부 LLM API, 로컬 모델, Agent 런타임, 도구 및 Worker
- 저장: 대화·작업 상태, 설정·메모리, 로그 및 결과물

## 설계 기준

- 접속 환경과 실행 환경을 분리한다.
- 중앙 서버를 세션과 작업 상태의 기준으로 삼는다.
- Session과 Execution을 별도 엔터티로 설계한다.
- 실행 이력과 결과를 영구 저장한다.
- 모델 공급자 교체와 설정 재사용을 고려한다.
- Agent에는 필요한 최소 권한을 부여한다.

## 검증 후 구체화할 항목

- Fork 또는 자체 개발 방식과 실행 런타임
- 중앙 호스트 및 원격 Worker 범위
- 데이터 모델, API와 세션 생명주기
- 인증·권한, Worker 통신, 장애 복구와 배포 구조

선택 근거는 [DECISIONS.md](DECISIONS.md)에 기록한다.
