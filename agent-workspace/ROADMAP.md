# 로드맵

갱신일: 2026-10-28. [현재 요구사항 v0.3](REQUIREMENTS.md)를 반영했다. 최초 [PRD v0.1](PRD.md)의 Phase 3 개발 실행 기능을 첫 버전으로 앞당긴다.

목표는 사용자가 지속적으로 사용할 완성품이다. 아래 단계는 구현·검증 순서이며, Phase 1은 정한 범위 안에서 일상적으로 쓸 수 있는 첫 제품 버전이다. 원본 PRD의 MVP 명칭은 최초 기획 기록으로 보존한다.

현재는 기획·상세 설계 준비 단계다. 문서 구성과 제품 방향 결정을 완료했고, Codex 연동 공식 문서를 기초 확인했다. 코드 구현, 실제 기기 테스트 및 연동 PoC는 아직 수행하지 않았다.

- [x] 자체 환경 중심 + 기존 도구 연결 방향 확정
- [x] 첫 버전 Mac mini 중앙 실행 확정
- [x] 개발 작업별 브랜치·worktree와 Git/GitHub 공유 방향 확정
- [x] 작업 브랜치 자동 커밋·push 및 사용자 승인 후 최종 병합 정책 확정
- [x] 일반 메시지의 추가 지시 처리와 별도 중단 버튼 정책 확정
- [x] 프로젝트 내부 의존성 자동 설치와 전역 설치·시스템 변경 승인 정책 확정
- [ ] 작업 생성·진행·승인·검토·병합 흐름과 권한 정책 구체화
- [ ] 추가 지시, 중단, 재접속 및 실행 실패 동작 구체화
- [x] 첫 버전의 여섯 가지 하네스 설정, 작업 순서 구성의 후속 확장 확정
- [x] OpenCode 우선 검증과 지속적인 실사용·확장성 기준 확정
- [ ] OpenCode 검증 버전·모델·인증 선택 및 설정·세션·실행 PoC
- [ ] 실행 엔진 연결 경계와 설정·데이터 이전 방안 설계
- [ ] Happier, OpenCode, OpenHands, Letta Code, OpenClaw와 Codex 연동 후보 조사; 조사 깊이·순서는 개발 요구사항 적합성에 따라 결정
- [ ] 두 worktree의 동시 코드 수정·명령 실행·테스트 및 통합 검증
- [ ] 기기 간 동일 작업 조회·추가 지시·명령 승인 PoC
- [ ] Mac mini 환경, 보안·라이선스, 데이터 모델과 최소 아키텍처 확정

완료 기준: 첫 개발 흐름에 필요한 실행 연결과 상태·승인 전달이 실제로 작동하고 기술 선택 근거가 기록된다.

## Phase 1 — 실사용 개발 워크스페이스 (첫 제품 버전)

- [ ] 자체 대화·프로젝트·작업 화면과 서버 기반 상태 저장
- [ ] Mac mini 실행 환경, Tailscale 및 애플리케이션 인증
- [ ] 개발 작업별 브랜치·worktree 할당과 작업 병행
- [ ] 검증 후 채택한 실행 연결을 통해 파일 수정·명령 실행·테스트 수행
- [ ] 프롬프트·모델·스킬·도구·메모리·권한 설정 및 Agent 프로필
- [ ] 하네스 템플릿 저장·선택·재사용과 실제 적용 설정 표시
- [ ] 명시적 메모리 선택·주입 및 범위 구분
- [ ] 엔진별 설정 지원 차이와 적용 실패 처리
- [ ] 대화·작업 이벤트와 진행 상태 조회
- [ ] 다른 기기에서 일반 메시지로 추가 지시 전달 및 전달·대기·반영 상태 표시
- [ ] 실행 중 지시 반영 미지원 연결의 대기열 처리
- [ ] 별도 중단 버튼과 중단 요청·완료 상태 표시
- [ ] 다른 기기에서 명령 실행 승인
- [ ] 프로젝트 내부 의존성 자동 설치 및 전역 설치·시스템 변경 승인 경계 검증
- [ ] 변경 코드, 실행 로그, 테스트 결과 및 결과물 확인
- [ ] 실패·재접속 상태 처리와 승인 중복 실행 방지
- [ ] 작업 브랜치 자동 커밋·push 및 결과 표시
- [ ] 변경·테스트 결과 검토와 사용자 승인 후 최종 병합 흐름 구현
- [ ] 작업 종료 및 worktree 보존·정리 정책 구현
- [ ] 기본 백업·복원과 서버 재시작 후 상태 복원 및 복구 한계 검증
- [ ] 기능 구현과 별도 버그 수정을 반복적으로 수행하는 실사용 검증
- [ ] 오류 발생 시 상태·원인·복구 조치 확인과 핵심 흐름의 회귀 검증

완료 기준: MacBook에서 시작한 개발 작업이 Mac mini에서 유지되고, 모바일에서 조회·추가 지시·승인·변경 확인을 수행한 뒤 MacBook에서 이어간다. 병행 작업의 파일 변경이 분리되고 검토·통합 흐름을 수행할 수 있다. 설정한 하네스를 재사용하고, 재접속·실패·재시작 시 기록 보존과 복구 흐름을 확인한다. 반복 실사용으로 이 흐름을 검증하며 구체적인 품질 수치·평가 기간은 Phase 0에서 정한다.

## Phase 2 — 연결 확장 및 템플릿·메모리 고도화

첫 버전에서 선택한 실행 연결 외의 지원 범위를 확장한다. API·로컬 모델·기존 구독 도구 중 최초 지원 조합은 Phase 0에서 결정하며, 특정 연결을 첫 버전에서 일괄 제외하는 계획은 아니다.

- [ ] 외부 API 및 Ollama 연결 지원 범위 확대
- [ ] 기존 구독형 Agent 도구 연결 지원 범위 확대
- [ ] 연결별 지원 기능과 제한 표시
- [ ] 템플릿 버전 이전·공유·관리 기능 확대
- [ ] 메모리 검색·정리와 프로젝트 간 범위 관리 고도화
- [ ] 추가 연결 도입 시 기존 설정·대화·작업 기록 유지 검증

## Phase 3 — 운영 안정성 및 실행 환경 확장

첫 버전의 기본 안정성·권한 처리는 Phase 1에 포함한다. 이 단계에서는 운영 범위와 복구 수준을 확장한다.

- [ ] 호스트 재시작·백업·복구 고도화
- [ ] 사용량·비용·성능 관측과 동시 실행 자원 관리 개선
- [ ] 실제 수요에 따라 원격 Worker 검토·도입

## Phase 4 — 예약 작업·루틴 및 비서 기반 확장

- [ ] 일회성 예약 메시지와 반복 예약
- [ ] 예약 Agent 실행과 루틴 정의
- [ ] 사용자 정의 작업 순서 구성과 여러 단계 실행·재개
- [ ] 실행 이력, 알림, 오류 처리 및 중복 실행 방지
- [ ] 일반 비서 기능의 구체적인 사용 사례와 범위 결정

일반 비서 기능의 모든 제공을 Phase 4로 고정한 것은 아니다. 초기에도 필요한 일부 기능은 후속 논의에서 선택하되 개발 우선순위를 유지한다.
